# Jingle Plan — план реалізації лендингу

Гілка: `jingle-plan-page`.

## Статус

- Дизайн обрано: **Мікс 1** (структура B, дизайн C: зелений hero, смужка-льодяник, картка-календар).
- На мобільному вкладки переваг зроблено компактними чіпами в один ряд над телефоном, щоб зміну екрана було видно без прокрутки.
- Етапи 1–5 реалізовані. Кнопки завантаження працюють через `links.json`, але реальних посилань і APK ще немає, тому вони показують «Незабаром». Етап 6 (Privacy / Terms) чекає на тексти або URL, етап 7 (домен, деплой) — на домен і доступ до Firebase.
- Lighthouse mobile (локально, емуляція): Performance 99, Accessibility 100, Best Practices 100, SEO 100, LCP 2,0 с, CLS 0.
- Інструкції зі запуску та керування посиланнями: `README.md`.

## 3. Архітектура

Стек із ТЗ: React + Vite + TypeScript + Tailwind CSS, Firebase Hosting, GA4.

Важливе уточнення до ТЗ: окремі індексовані URL `/uk/` та `/en/` не працюють на чистому SPA (пошуковики й Open Graph бачать порожній `index.html`). Тому потрібен статичний пререндер: `vite-react-ssg` або власний скрипт пререндеру після збірки. Бекенд при цьому не потрібен.

```
jingle-plan-page/
  public/
    config/links.json        # посилання на магазини, no-cache
    config/apk.json          # версія, розмір, sha256 (генерується)
    downloads/jingle-plan.apk
    sitemap.xml, robots.txt, og/*.jpg
  src/
    app/                     # роутинг /uk, /en, пререндер
    sections/                # hero, how-it-works, benefits, outcome, download, footer
    components/              # phone-frame, store-button, apk-card, lang-switch, consent-banner
    i18n/                    # uk.ts, en.ts
    analytics/               # ga4, utm, consent, events
    config/                  # завантаження links.json
    assets/                  # webp/avif скриншоти
  scripts/
    build-apk-meta.mjs       # рахує size + sha256, пише apk.json
  firebase.json
```

### Посилання без редеплою

`links.json` читається клієнтом при завантаженні (з `Cache-Control: no-cache`), фолбек — зашите значення:

```json
{
  "ios": { "url": "https://apps.apple.com/app/idXXXXXXXXX" },
  "android": { "type": "apk", "url": "/downloads/jingle-plan.apk" }
}
```

Після публікації в Google Play змінюється лише файл: `"type": "play", "url": "https://play.google.com/store/apps/details?id=com.murarova.jingleplan"`. Блок версії/SHA-256 та інструкція ховаються автоматично.

### Firebase Hosting

```json
{
  "hosting": {
    "public": "dist",
    "cleanUrls": true,
    "trailingSlash": true,
    "redirects": [{ "source": "/", "destination": "/uk/", "type": 302 }],
    "headers": [
      {
        "source": "/downloads/**/*.apk",
        "headers": [
          { "key": "Content-Type", "value": "application/vnd.android.package-archive" },
          { "key": "Content-Disposition", "value": "attachment; filename=\"jingle-plan.apk\"" },
          { "key": "Cache-Control", "value": "public, max-age=300" }
        ]
      },
      {
        "source": "/config/**",
        "headers": [{ "key": "Cache-Control", "value": "no-cache" }]
      }
    ]
  }
}
```

Редирект `/` потрібно робити за `Accept-Language` на клієнті, а не жорстко на `/uk/`, інакше англомовна реклама не працюватиме. Деталь вирішується на етапі 3.

Hosting краще створити окремим сайтом у проєкті `advent-calendar-12` (multi-site), щоб не змішувати з Functions додатка.

APK не комітити в git (розмір). Класти під час деплою з артефакта збірки або з Cloud Storage; `build-apk-meta.mjs` запускається перед `firebase deploy`.

### Події GA4

| Подія | Реалізація |
| --- | --- |
| `page_view` | при відкритті, з `language` |
| `click_app_store` | клік на кнопку, параметр `placement` (hero / download) |
| `click_android_download` | клік на кнопку Android |
| `apk_download_started` | див. ризик нижче |
| `click_privacy_policy` | клік у footer |

UTM `source`, `medium`, `campaign`, `content` зберігаються в `sessionStorage` при першому візиті й додаються параметрами до подій. Key events у GA4: `click_app_store`, `click_android_download`.

## 5. Що потрібно від тебе

Блокує імплементацію:

1. Вибір макета (A / B / C або мікс).
2. Домен (`jingle-plan.app` або інший) та чи є доступ до DNS.
3. Посилання на App Store (`id…`).
4. Підписаний release APK і keystore-політика (див. ризики).
5. Email підтримки та акаунт Instagram (чи показувати).
6. Тексти або URL Privacy Policy / Terms: у додатку вони приходять із env (`EXPO_PUBLIC_TERMS_URL`, `EXPO_PUBLIC_PRIVACY_URL`), у репозиторії значень немає.
7. Ціна й умови підписки Jingle Plan+ (у коді ціни немає, вона з магазину), а також чи є пробні дні. Від цього залежить формулювання в секції 5.
8. GA4 Measurement ID, Meta Pixel ID (якщо реклама).

Щодо матеріалів:

- Є 4 скриншоти (Головна, Плани, Прогрес, Альбом), але вони 473×1024 — для різкості на retina потрібні оригінали 1170×2532 або більші.
- У ТЗ у секції 4 вказані екрани «Підсумки, Плани, Альбом». Скриншота «Підсумки» серед наданих немає, у макетах замість нього «Прогрес». Потрібен реальний скриншот цього екрана.
- Для OG-прев'ю потрібна картинка 1200×630 (я зроблю з лого та скриншотів).

## 6. Ризики та нюанси

- **«Безкоштовно».** У макетах написано «безкоштовно встановити · повний доступ — за підпискою Jingle Plan+». Слово «безкоштовно» без пояснення про підписку не використовувати.
- **Підписка в секції 5.** Нотатка про автопоновлення береться з paywall (`billingNoteIos/Android`) і має бути видима до кнопок завантаження.
- **Оновлення APK через Google Play.** Щоб користувачі зі встановленим APK потім оновилися з Play без перевстановлення, APK має бути підписаний тим самим ключем, що й Play App Signing, і мати той самий package `com.murarova.jingleplan`. Якщо в Play уже згенерований власний ключ підпису, APK із сайту треба підписувати саме ним або зареєструвати наявний ключ у Play App Signing. Перевірити до першої публікації APK.
- **Встановлення поза Google Play.** Перед запуском перевірити актуальні вимоги Android до верифікації розробників для sideload: вони змінюються і можуть вплинути на інструкцію.
- **`apk_download_started`.** Браузер не повідомляє, що завантаження справді почалося. Реально доступно: подія при кліку плюс перевірка, що `HEAD /downloads/jingle-plan.apk` повертає 200. Точніший підрахунок вимагатиме Cloud Function-проксі, для першої версії це зайве.
- **Cookie-згода.** GA4 та Meta Pixel вантажити лише після згоди (Consent Mode v2, за замовчуванням `denied` для ЄС). Без цього подій з ЄС не буде, і це юридичний ризик.
- **Кнопка App Store.** Для фінальної версії використати офіційний бейдж Apple (SVG із Apple Marketing Resources). У макетах стоїть нейтральна кнопка-заглушка.
- **Розмір APK.** Firebase Hosting дозволяє великі файли, але кожен деплой перезавантажує його, якщо файл змінився. Стежити за розміром сховища та трафіком.
- **Сезонність.** Основний трафік у листопаді-грудні, тож запуск краще не відкладати; Lighthouse і SEO-тонкощі можна дотискати вже після запуску.
